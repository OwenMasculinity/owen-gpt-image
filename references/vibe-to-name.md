# 感觉 → 真名 映射表

> 用途：当用户（或 agent）只说得出「感觉」、说不出设计术语时，用这张表把感觉翻译成能填进三槽位的真名。
>
> **这张表是给 agent 查的，不是给用户背的。** 用户永远只需要说人话。

## 使用规则（agent 必读）

1. **先判空**：用户的话里只有形容词 + 场景（「高级感」「温暖」「科技感」），没有任何专有名词 → 触发本表。
2. **查表拿候选**：一个感觉词对应 3 个候选真名，**优先选带 🌐 的**（大众可识别，用户能判断「像不像」）。
3. **不要替用户拍板**（除非用户说「你看着办」）：把 3 个候选 + 一句话区别给用户选，**一轮为限**。
4. **仍然填不出 → 用元 prompt**（见文末）：让模型先自报 3 个参照，再按它生成。
5. **拿到真名后照常跑 5 项自检** —— 本表只解决「名字从哪来」，不替代质量门禁。

## 元 prompt 模板（兜底：连表都查不到时）

```
[用户需求一句话]。我不确定该用什么风格参照，请你先说出 3 个最匹配的
（设计师 / 品牌 / 媒介范式）参照，各用一句话说明你会从它身上借什么，
然后选一个最合适的，按它生成。
```

**为什么有效**：模型的知识库远大于用户的知识库，让它替用户补名字。
**副作用是好的**：它每次都会解释「借了什么」，用户被动积累名字库，用久了就懂了。

变体 · 让用户参与选：

```
请给出 3 个参照，我会选一个，你再生成。
```

---

## 三条硬约束

1. **禁止**因为用户说不出名字就直接堆形容词生成 —— 那正是红线 3 禁止的。
2. **禁止**开放题追问（「你想要什么风格？」）—— 小白答不上来，只出选择题，且自带默认值。
3. **最多一轮**追问。用户不回就按默认值生成，不要卡住。
